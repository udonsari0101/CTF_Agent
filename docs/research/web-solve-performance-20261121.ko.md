# 웹 풀이 지연 분석과 개선 (2026-11-21)

이 문서는 대회 작업공간의 비공개 진단 내보내기를 집계한 결과와 공개 코드의 변경 근거를 기록한다. 문제 파일, Flag, 인증 정보, 원격 주소, 원문 활동 로그는 포함하지 않는다.

## 관찰과 원인 구분

- 분석한 웹 풀이의 첫 원격 관찰은 시작 후 15~33초였다. 접속 준비 자체보다, 확인된 취약점 경로가 없는 상태에서 가설과 후보를 계속 넓힌 시간이 더 컸다. 장시간 실행 두 건은 각각 약 142분·125분에 셸 호출 시작 601회·567회를 기록했고 검증된 Flag 경로 없이 종료됐다. 이 수치는 활동량이지 중복 명령률이나 해결률이 아니다. 내보내기에는 명령·출력 원문이 없어 동일 명령 반복률을 계산할 수 없다.
- 네 웹 작업이 같은 시각에 `awaiting_credential`로 바뀌어 약 238초 후 재개됐다. 공급자 인증 대기는 문제 풀이 추론 시간과 분리해서 해석해야 한다. 상위 인증 실패 원인은 이 로그만으로 확정할 수 없다.
- 이전 버전에는 명령 실행기와 브라우저 경로 오류도 있었다. 이 오류는 별도 수정과 canary 검사 대상이며, 이번 변경만으로 과거 장시간 실행 전체가 빨라졌다고 볼 수 없다.
- 본문에 참고용 URL 하나만 있어도 원격 서버로 저장되던 오탐을 재현했다. 반대로 CTFd와 같은 도메인의 명시적인 `/proxy/...` 서비스 URL은 누락됐다. 두 경우 모두 첫 탐색 방향을 왜곡할 수 있다.

## 이번 변경

1. 원격 주소 추출은 문맥, 링크 표제, 문서 경로, CTFd 자체 경로를 구분한다. 가이드 링크는 원격 서버로 승격하지 않고, 같은 도메인의 명시적인 서비스 경로는 저장한다. 명시적으로 입력된 원격 필드는 계속 우선한다. 애매한 복수 주소는 첫 번째를 임의로 선택하지 않는다.
2. `ctf-browser-act --capture-api-json`은 필요할 때만 동일 출처의 완료된 XHR/fetch JSON 응답을 최대 8개, 각 4 KiB까지 보여 준다. 기본 출력은 바뀌지 않는다. 로그인 뒤 브라우저에서만 볼 수 있는 API 결과를 확인하기 위해 쿠키를 잃는 별도 요청을 반복할 필요를 줄이는 기능이다. URL의 쿼리 값은 가리지만 응답 본문은 의도적으로 관찰하므로 결과를 공개 write-up에 그대로 옮기지 않는다.
3. 웹 플레이북의 시작을 단일 취약 핸들러 가정에서 실제 목표·정상 요청·입력→도달 경로 확인으로 바꿨다. 대규모 경로 검색·payload 생성·키 후보 시험 전에는 관찰 근거, 반증 결과, 요청/시간 상한을 정하게 했다. 기본 `ffuf` 예시는 낮은 동시성과 요청률로 시작한다. 자동 시간 초과나 강제 가설 전환은 추가하지 않았다. 유효한 관찰을 계속 얻는 장기 작업을 단순 호출 수로 끊으면 오히려 해결률을 떨어뜨릴 수 있기 때문이다.

## 검증과 성능 판정 범위

본문 주소 분류 45개 사례, 수동 등록·편집·복제, CTFd 동기화 13개, 제출 인증 12개, 첨부 배치 5개가 통과했다. 선택형 브라우저 관찰은 실제 Chromium과 팝업 지연 응답을 포함한 6개 검사가 통과했고, 기존 브라우저 세션 검사 6개 중 4개가 통과했으며 Linux 컨테이너 전용 2개는 로컬 Windows에서 건너뛰었다. 컨테이너 통합 smoke는 CI 이미지 빌드에서 확인한다.

이 검증은 **정확한 주소 저장, 도구 관찰, 회귀 방지**를 입증한다. 대회 원격 서버가 종료된 상태이고 로컬 Docker 엔진도 실행 중이지 않아, 동일 문제·동일 모델·동일 제한에서 Flag 획득 시간이나 정답률의 전후 차이는 측정하지 못했다. 다음 성능 판정에는 새 문제의 독립 판정기와 격리된 서비스 인스턴스를 준비하고, 같은 모델·계정·이미지·시간 예산으로 이전/새 하네스를 짝지어 비교해야 한다. 최초 단서, 원격 오류, 공급자 대기, Flag 후보, 공식 정답 판정의 시간을 분리한다. [NYU CTF Bench](https://nyu-llm-ctf.github.io/)처럼 난이도와 분야가 다양한 평가가 필요하며, [plain-agent 연구](https://arxiv.org/abs/2412.02776)와 [웹 CTF 하네스 통제 비교](https://cyphlon.com/research/llm-agents-web-pentest-ctfs/)도 지침이나 계획 구조를 더하는 것만으로 성능 향상을 가정해서는 안 된다는 참고 자료로 사용했다. 두 연구의 성적을 CTF Agent의 실측 성적으로 전용하지 않는다.
