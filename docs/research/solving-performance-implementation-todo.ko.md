# 풀이 성능 개선 작업 목록

이 문서는 [연구·평가 설계](solving-performance-research.ko.md)를 실제 코드 변경으로 옮기기 위한 체크리스트다. `완료`는 코드와 회귀 검사를 뜻하며, 정답률·속도 향상은 같은 조건의 실제 문제 풀이와 독립 판정 전에는 주장하지 않는다. 비공개 문제, Flag, 인증 정보는 저장소에 넣지 않는다.

## 이번 작업

- [x] 현재판의 도구·프롬프트·계측·공유 기능을 확인하고 중복 구현을 피한다.
- [x] 풀이 시간 계측 현황을 대조한다. coordinator는 큐·준비·첫 활동·Flag·write-up 시각을, worker는 첫 모델 응답·첫 도구 결과를 기록한다. 공식 CTFd 판정은 별도 경로에 있으므로 실제 벤치 실행기는 두 기록을 독립적으로 연결해야 한다.
- [x] 최근 루트 셸 결과 6개 중 같은 명령과 출력·종료 상태가 3번 반복되면 다음 턴에만 다른 검증을 제안한다. 출력이 바뀌는 재검사와 하위 에이전트의 명령은 제외하고 풀이를 강제 중단하지 않는다.
- [x] 초기 지침을 분야명 누락에도 적용 가능한 간결한 형태로 바꾸고, 직접 Flag를 검증할 수 있는 경우 불필요한 `solver.py` 작성을 생략한다.
- [x] 웹·리버싱·포너블·포렌식·암호 도구와 playbook을 대조한다. 웹은 소스가 있는 경우에도 첫 실제 관찰을 앞당기고, 원격이 없는 경우에는 로컬 관찰로 대체한다. 나머지 분야의 큰 도구 추가는 현재 증거가 없어 보류한다.
- [x] 도구 호출·원격 없음·재개·Flag 오답·형제 풀이 공유 회귀 검사를 수행한다.
- [ ] 기준선과 후보판의 작은 짝지은 평가를 준비하고, 실제 풀이가 가능한 사례에 대해서만 속도·정답·비용을 보고한다.
- [ ] 결과가 확인된 변경만 기본값으로 채택하고, 변경 파일·테스트·남은 한계를 기록한다.

## 현재 검증 기록 (2026-11-13)

- `check_activity_provenance.py`: 15개 통과. 루트/하위 구분, 같은 명령·출력만 감지, 바뀐 출력·짝 없는 완료 제외.
- `check_solver_progress_nudges.py`: 19개 통과. 반복 사실은 다음 턴에만 전달되고 기존 재시도·원격 요청 정책을 유지한다.
- `check_tool_playbook_contract.py`: 7개 통과. 직접 추출, 분류 미지정, 원격 없음 및 도구 문구 확인.
- 재개·시각·원격 본문·CTFd 제출·형제 풀이·상태 복구 관련 검사 통과. Windows에서 실행하지 않는 Linux 전용 상태 복구 사례 3개는 기존대로 건너뛰었다.
- 비공개 `benchmark_problems/`에 37개 case 디렉터리와 manifest·실험 계획이 있음을 확인했다. 이번 후보판의 짝지은 모델 풀이와 공식 oracle 결과는 아직 없다. 현재 Windows Docker 엔진이 구동되지 않는다. `check_benchmark_plan.py` 3개와 `check_benchmark_report.py` 14개는 통과했지만 이 검사는 결과 형식만 검증한다. 단위 검사를 정답률 향상 수치로 해석하지 않는다.

## 작은 모델 평가를 재개할 때

개발셋에서 서로 다른 네 분야의 `ctftiny-cry-babycrypto`, `ctftiny-for-1black0white`, `ctftiny-rev-whataxor`, `ctftiny-msc-ezmaze`를 먼저 사용한다. v0.4.72와 후보판의 동일 계정·모델·추론·CLI·이미지 정책을 맞추고 순서를 교차한다. 각각 한 번씩의 짝지은 예비 실행은 운영 결함을 찾는 용도이며, 성능 우열을 선언하는 표본이 아니다. 첫 예비 실행이 통과하면 반복 수와 별도 보류셋을 실행 **전에** 고정한다. 답이 이미 공개된 문제이므로 외부에서 정답을 찾은 경우를 별도 분류하고, 문제의 기존 Flag나 oracle을 solver 작업공간으로 복사하지 않는다. 서비스형 웹·포너블은 격리된 표적과 독립 judge 준비 후에만 합류한다.

## 판정 기준

1. 동일 문제 입력, 모델·추론 수준, 계정, CLI·이미지, 시간/토큰 예산으로 비교한다.
2. 공식 CTFd 또는 독립 oracle의 `accepted`만 성공으로 센다. Flag 후보나 작성된 write-up은 성공이 아니다.
3. 15·30·60분 성공 수, 성공까지 활성 풀이 시간, 오답·추가 입력 오탐, 토큰·CPU/RAM을 함께 본다.
4. 어려운 한 문제의 개선을 전체 분야의 개선으로 일반화하지 않는다. 도움이 없거나 악화되면 해당 변경을 되돌린다.
