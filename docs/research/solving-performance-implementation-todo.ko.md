- [x] v0.4.75 배포 후 리버싱 문제를 원격 주소 없이 다시 등록·실행해 실제 풀이 경로와 독립 정답 해시 일치를 확인했다.

이번 범위의 실측값과 미검증 경계는 [2026-11-14 풀이 경로 검증과 평가 결정](solving-performance-evidence-20261114.ko.md)에 있다. 중단된 96회 시험과 별도 AB/BA 반복은 사용자의 벤치마크 축소 지시에 따라 이번 출시 조건에서 제외했다. 성능 향상을 입증했다고 표시하지 않는다.

이 문서는 [연구·평가 설계](solving-performance-research.ko.md)를 실제 코드 변경으로 옮기기 위한 체크리스트다. `완료`는 코드와 회귀 검사를 뜻하며, 정답률·속도 향상은 같은 조건의 실제 문제 풀이와 독립 판정 전에는 주장하지 않는다. 비공개 문제, Flag, 인증 정보는 저장소에 넣지 않는다.

## 운영 워커 예비 비교 (2026-11-14)

- 네이티브 CLI 차단을 우회하려 하지 않고 실제 서비스 워커 경로로 `ctftiny-cry-babycrypto`를 v0.4.72와 v0.4.74에서 각각 새 문제로 한 번 실행했다. 문제 본문·암호문, 분야, 원격 설정, 계정, `gpt-6-sol`/`medium`, Ultra 꺼짐, 네트워크 정책과 Codex CLI 0.165.0의 바이너리 해시가 같았다. 두 문제의 이름에는 버전 식별용 접미사가 달랐다.
- 두 실행 모두 완료됐고 Flag가 작업공간 밖의 비공개 독립 정답 해시와 일치했다. 생성부터 종료까지 88.2초 대 77.1초, 실행 시작부터 Flag까지 54.2초 대 34.4초였다. 큐·준비·write-up 시간까지 포함하는 전체 시간과 Flag까지의 활성 시간을 구분한다. 수동 개입은 없었다.
- 이는 **단일 쉬운 암호 문제의 순서가 고정된 예비 실행**이다. 모델 응답 변동과 워커 이미지 차이를 분리할 수 없고 문제명이 완전히 같지 않으며 비용 자료도 없다. 따라서 전체 정답률·속도 향상이나 v0.4.74의 인과적 우위를 주장하지 않는다. 네 분야·순서 교차·반복·보류셋의 정식 짝지은 평가는 여전히 미완료다. 원시 로그와 oracle은 비공개로 보관하고 저장소에는 올리지 않는다.

## 작은 모델 평가를 재개할 때

개발셋에서 서로 다른 네 분야의 `ctftiny-cry-babycrypto`, `ctftiny-for-1black0white`, `ctftiny-rev-whataxor`, `ctftiny-msc-ezmaze`를 먼저 사용한다. v0.4.72와 후보판의 동일 계정·모델·추론·CLI·이미지 정책을 맞추고 순서를 교차한다. 각각 한 번씩의 짝지은 예비 실행은 운영 결함을 찾는 용도이며, 성능 우열을 선언하는 표본이 아니다. 첫 예비 실행이 통과하면 반복 수와 별도 보류셋을 실행 **전에** 고정한다. 답이 이미 공개된 문제이므로 외부에서 정답을 찾은 경우를 별도 분류하고, 문제의 기존 Flag나 oracle을 solver 작업공간으로 복사하지 않는다. 서비스형 웹·포너블은 격리된 표적과 독립 judge 준비 후에만 합류한다.

## 판정 기준

1. 동일 문제 입력, 모델·추론 수준, 계정, CLI·이미지, 시간/토큰 예산으로 비교한다.
2. 공식 CTFd 또는 독립 oracle의 `accepted`만 성공으로 센다. Flag 후보나 작성된 write-up은 성공이 아니다.
3. 15·30·60분 성공 수, 성공까지 활성 풀이 시간, 오답·추가 입력 오탐, 토큰·CPU/RAM을 함께 본다.
4. 어려운 한 문제의 개선을 전체 분야의 개선으로 일반화하지 않는다. 도움이 없거나 악화되면 해당 변경을 되돌린다.
